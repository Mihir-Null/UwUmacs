# UwUmacs Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a literal-leader Meow layer with discoverable menus and explicit integrations for the currently enabled configuration, then make that layer reusable outside Lambda.

**Architecture:** Meow retains editing and states. UwUmacs owns ordinary prefix maps, a reversible state-aware emulation layer, a lazy integration registry and discovery. Package acquisition and personal policies remain in the host configuration.

**Tech Stack:** Emacs Lisp, GNU Emacs 30.1+, Meow, built-in keymaps and Which-key, existing completion packages, ERT, Org tangling, Python 3 for planning coverage checks.

**Spec:** [UwUmacs architecture contract](../specs/2026-09-13-uwumacs-design.md)

## Global Constraints

- Minimum supported core runtime: GNU Emacs 30.1.
- First exercised host: native Windows Emacs 31.1, with GUI and daemon/terminal checks kept distinct.
- Initial Meow compatibility target: installed Meow snapshot 20260714.1200. Record its source revision before standalone release; do not invent an upstream tag for this snapshot.
- Meow owns editing grammar, selection, grabs, Beacon and states. UwUmacs owns its keymaps, registry, menu labels and compatibility hooks.
- UwUmacs core has no package manager, network access, machine paths, fonts, themes or `lem-*` dependencies.
- Keep PowerShell default, MSYS2 explicit, language-server startup opt-in and the independent notes vault untouched.
- Preserve the current completion stack and the frames-only preference. Frames-only is a host-selected adapter, not a mandatory dependency of core.
- Every runtime change is authored in literate Org and tangled; generated Lisp remains tracked. Startup never tangles.
- Keep generated files directly in `lambda-library/lambda-user/` initially. The current tangle validator rejects nested outputs; this design does not weaken that boundary.
- Do not modify installed files under `var/elpa/`. Preserve Lambda provenance and existing licenses.
- User overrides win deterministically. Re-enabling a mode or reloading an adapter must not duplicate bindings, hooks, advice or formatters.
- Package integrations are selected explicitly. Loading core must not force every selected target package to load.
- Temporary input interfaces retain control. UwUmacs must not globally commandeer minibuffers, Transient, query-replace, isearch or terminal character input.

The execution scope is enabled configurations. The [inventory-only appendix](../../uwumacs/integrations.md#inventory-only-not-scheduled) has no execution tasks. A configured package that loads lazily on invocation remains in scope. An unavailable guarded package does not.

For new ERT files, P00 creates a test loader that only initializes the existing package directory and adds `lambda-library/lambda-user` to load-path. It does not load the personal config or install anything.

```elisp
;;; tests/uwumacs-test-helper.el -*- lexical-binding: t; -*-
(require 'ert)
(require 'cl-lib)
(require 'package)
(when-let* ((directory (getenv "EMACS_DOTS_TEST_PACKAGES")))
  (setq package-user-dir directory))
(package-initialize)
(add-to-list 'load-path
             (expand-file-name "../lambda-library/lambda-user"
                               (file-name-directory load-file-name)))
(require 'meow)
(provide 'uwumacs-test-helper)
```

Each test file explicitly requires the relevant implemented core/adapter after this helper. Tests must save and restore any global Meow/UwUmacs state and user maps they change. Use `unwind-protect`; do not force an already-active Meow state minor mode a second time. Prefer the normal interactive state transitions in graphical fixtures.

Focused run, replacing the file with the current wave's exact file:

```powershell
& $uwuEmacs -Q --batch -l tests/uwumacs-test-helper.el -l tests/uwumacs-core-tests.el -f ert-run-tests-batch-and-exit
```

P06 creates `tests/uwumacs-gui-tests.el` and a runner that starts a dedicated ordinary GUI Emacs using the repository init directory, schedules tests after window setup, writes a UTF-8 result and exits only that dedicated process. Batch initialization is not the GUI startup gate. Use a unique server name and never terminate user-owned Emacs processes.

## 6. Evidence and progress format

Create `docs/uwumacs/progress.json` when implementation starts, keyed by catalogue ID:

```json
{
  "I001": {
    "status": "pending",
    "commit": null,
    "target_version": null,
    "tests": [],
    "limitations": []
  }

```

Allowed statuses: pending, in-progress, verified, capability-limited. Only verified entries count as executed acceptance. A capability-limited entry names the unexecuted behavior and unavailable capability. This initial pending example is not evidence of implementation.
