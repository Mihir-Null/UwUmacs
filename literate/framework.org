* The ownership boundary

Emacs core provides the editor and its built-in libraries. Lambda-Emacs is an
external configuration framework by Colin McLear. Emacs-Dots supplies the user
selection and local extensions. A =lem-= name usually belongs to Lambda;
=starter-= names belong to this repository. Package names such as Meow, EAT and
dashboard identify separate external projects.

The imported Lambda revision and original hashes are recorded in
[[file:../docs/LAMBDA-UPSTREAM.json][LAMBDA-UPSTREAM.json]]. The original GPL license is in [[file:../LICENSE][LICENSE]].
This chapter documents the vendor boundary; it does not tangle vendor modules.
Only the inherited root bootstrap is presented as literate code in
[[file:10-bootstrap.org][the bootstrap chapter]].

* The local integration patch
:PROPERTIES:
:CUSTOM_ID: local-integration-patch
:END:

[[file:../lambda-library/lambda-setup/lem-setup-settings.el][lem-setup-settings.el]] contains the existing local integration patch:

- Customize saves to persistent =var/etc/custom.el= instead of disposable cache.
- The settings module leaves =private.el= loading to the user composition root.
  That gives it one load, after platform defaults are defined and before later
  modules consume the overrides.

The patch predates this literate conversion. All other vendor module files
remain unchanged. Root startup files retain their Lisp forms but now carry a
generated-source notice and block-derived formatting, so byte hashes of those
two generated files differ from the original import. The original hashes are
retained as provenance, not replaced by hashes of the generated copy.

* Module selection is separate from module availability

The inventory below is derived from direct requires in the current user
composition. A module can load dependencies transitively; "not directly
selected" does not prove its feature can never be loaded. The catalogue also
contains alternative upstream presentations and workflows that are not part
of the selected user setup.

To enable another module, read its source and dependencies, add the require in
[[file:20-user-policy.org][user policy]], and check whether its package topic must be added to the early
allowlist. Do not enable the entire upstream catalogue just to obtain one command.

* Updating the snapshot

Follow [[file:../docs/UPSTREAM.md][the upstream update procedure]]. Update the bootstrap Org chapter when importing root-file changes, retain original hashes and attribution, and keep the local settings patch explicit. Run the tangle check, isolated startup test and ordinary graphical startup before deployment.
